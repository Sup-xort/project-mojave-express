# 모하비 익스프레스 스탬프 앱

`plan.md`에 정의된 손님용 스탬프 카드 시스템의 구현체. Node.js + Express + SQLite(WAL).
개인정보(이름·전화번호·이메일 등)를 받지 않고, 별명 + PIN 4자리만으로 이용한다.

## 스탬프 → 쿠폰 → 리워드

```
QR 적립 → 스탬프 10개(COUPON_STAMP_COST) → 🎟 쿠폰 1장 (자동 변환)
                                            ↓ 손님이 "사용하기"
                                  쓰는 시각의 시간대가 리워드를 결정
                                            ↓ 사장님 승인
                                        사용 완료
```

- **쿠폰 변환은 자동이다.** 기준 수가 차는 순간 서버가 스탬프를 차감하고 쿠폰을 발급한다.
  손님이 누를 것은 없고, 넘친 스탬프는 다음 판으로 이월된다. 한 번에 여러 장도 나온다.
- **쿠폰 자체에는 이름이 없다.** 무엇으로 바꿀지는 쿠폰을 *쓰는 시각*이 정한다. 사장님이 리워드마다
  운영 시간대(`start_min`~`end_min`, `STORE_TZ` 기준)를 정해두면, 그 시각에 열려 있는 리워드가
  교환 대상이 된다. 시간대가 겹쳐 여러 개가 열려 있으면 손님이 그중 하나를 고른다.
- **스탬프 차감은 쿠폰 발급 때 한 번뿐이다.** 사장님 승인은 쿠폰을 `used`로 확정할 뿐 스탬프를
  건드리지 않는다. 요청을 취소하거나 `REDEMPTION_TTL_SEC`이 지나 만료되면 쿠폰은 미사용으로 돌아온다.
- **쿠폰 유효기간**은 기본이 무기한이고, 사장님 앱 [설정] 탭에서 일수로 바꾼다(0이면 무기한).
  기간은 쿠폰을 *발급하는 시점*에 계산해 `coupons.expires_at`에 새겨지므로, 나중에 정책을 바꿔도
  이미 손님이 갖고 있는 쿠폰의 만료일은 변하지 않는다. 승인 대기 중(`pending`)인 쿠폰은 기간이
  지나도 만료시키지 않는다 — 기간 안에 요청한 손님이 승인 몇 분을 기다리다 손해 보면 안 되기 때문이다.

## 설정을 어디서 바꾸나

| 값 | 위치 | 반영 |
|---|---|---|
| 쿠폰 유효기간 (`coupon_ttl_days`) | 사장님 앱 [설정] 탭 → `settings` 테이블 | 즉시 (이후 발급분부터) |
| 쿠폰 1장당 스탬프 (`COUPON_STAMP_COST`) | 서버 `.env` | 재시작 필요 |
| 매장 시간대 (`STORE_TZ`) | 서버 `.env` | 재시작 필요 |
| 리워드 이름·시간대 | 사장님 앱 [리워드 관리] | 즉시 |

## 폴더 구조와 손님/사장님 경계

이 저장소는 **손님용 앱**과 **사장님용 앱**을 함께 구현한다. 둘은 코드상으로 확실히 분리되어
있고(라우터, 미들웨어, 세션 쿠키가 모두 별개), DB만 공유한다.

```
src/
  routes/customer/   손님용 API (/api/signup, /api/login, /api/stamp, /api/coupons, /api/coupon/use 등)
  routes/owner/       사장님용 API (/api/owner/setup, /login, /dashboard, /qr, /rewards, ... 등)
  services/           도메인 로직 (세션, QR, 스탬프, 쿠폰, 리워드, 로그인 시도 제한, 오너 계정)
  middleware/         손님 세션 인증, 오너 세션 인증, 에러 응답, rate limit
  db/                 SQLite 스키마 + 연결
  cron/               만료 QR/쿠폰 사용 요청/로그인 시도 기록 정리
public/                손님용 웹앱 (바닐라 HTML/CSS/JS, 빌드 단계 없음)
owner/                 사장님용 웹앱 (바닐라 HTML/CSS/JS, 빌드 단계 없음)
deploy/                Caddyfile, systemd 유닛, DuckDNS 갱신 스크립트
scripts/backup.sh       SQLite 백업 스크립트
```

## 로컬 실행

```
npm install
cp .env.example .env
# .env에서 PIN_PEPPER, OWNER_PASSWORD_PEPPER를 채우고, 로컬 http 테스트를 위해 COOKIE_SECURE=false로 설정
npm run dev
```

- 손님용 앱: http://localhost:3000/
- 사장님용 앱: http://localhost:3000/owner/ — 처음 접속하면 계정 생성(아이디+비밀번호) 화면이
  뜨고, 이후에는 로그인 화면으로 이어진다. 별도의 관리자 키나 사전 프로비저닝이 필요 없다.

## 구현 범위와 의도적으로 뺀 것

- `plan.md` 10절에 따라 PIN 찾기·계정 복구·손님 간 스탬프 전송·서드파티 분석/광고·푸시 알림은
  만들지 않았다.
- 쿠폰에는 유효기간이 없다. `coupons.expires_at` 컬럼만 미리 두고 항상 NULL로 둔다.
- QR 적립 동선은 세 가지다: 앱 내 카메라 스캐너(주 동선), 기본 카메라 앱으로 찍으면 열리는
  URL 딥링크(`/s/<token>`), 카메라를 못 쓸 때의 수동 코드 입력.
- 사장님 계정은 매장 태블릿 한 대에서 쓰는 것을 가정해 여러 직원 계정 관리 UI는 만들지 않았다
  (DB 스키마 자체는 여러 계정을 담을 수 있지만, 최초 설정 화면은 계정이 하나도 없을 때만 열린다).
